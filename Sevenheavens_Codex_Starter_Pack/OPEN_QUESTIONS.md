# Open intake questions
Ask in plain language. Reuse answers already provided. These are unresolved choices, not reasons to leave independent work unfinished.

1. What exact first content piece should the prototype recreate, and which details of your reference matter most to you?
   Capture: reference, content family, structure versus aesthetic adaptation, duration, text/music requirements, hard exclusions.

2. What footage will define the first test, where is it stored, and how representative is it of your normal shoots?
   Capture: selected folder/files, approximate clip count/duration, product/outfit grouping, camera/iPhone formats, reference and chosen music excerpt. No need to upload a whole archive to begin.

3. What processing boundary and spending limit should the first build use?
   Capture: fully local versus specified permitted model services, what media may leave the machine, existing provider access without requesting secret values in chat, maximum test spend. A coding subscription is not automatically an application API credential.

4. What must you be able to change after generation?
   Capture: finished MP4 plus shot-replacement controls, or a fully editable native Resolve/OpenShot project as a first-version requirement. Ask about the desired outcome; do not force the user to design adapters.

5. Where must the first version run, and who needs to use it?
   Capture: Tony's Mac model/RAM/free working space, his computer only versus another team machine, and later multi-user needs. Discover hardware locally when access allows; do not repeat information already known.

## Decision record
For each answer store:
question; user answer; source/date; implication; status; unresolved follow-up.
Keep proposed defaults separate from accepted choices.

## Consequential blocker example
Blocked stage: real visual source selection.
Observed failure: selected provider cannot accept the configured video/frame input.
Effect: the application can render, but AI shot selection cannot be evaluated.
Already tried: list actual checks only.
Open question: Which supported processing route should we use within your media and spending boundaries?
Independent work: continue import, job state, UI and deterministic render verification.

Do not substitute a generic "please clarify" or claim an assisted demo is a trained autonomous editor.
